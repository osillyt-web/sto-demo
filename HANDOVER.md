# Передача и запуск: от демо до рабочего сайта

Документ для владельца и для того, кто будет разворачивать. Всё, что требует аккаунтов
(хостинг, домен, бот), собрано в одном месте — по порядку.

## 0. Что уже есть в проекте

| Что | Где |
|---|---|
| Сайт: 17 страниц, онлайн-запись по слотам, мессенджеры, отзывы, портфолио | `/`, `/services/*`, `/brands/*`, `/cases` |
| Админка: заявки, календарь загрузки, услуги, контакты, слоты, аналитика | `/admin` |
| Страница записи для клиента с подтверждением и отменой | `/r/<token>` |
| Резервные копии базы (7 последних, ежедневно в 03:00) | `backups/sto-*.db` |
| Мониторинг: health-check для внешнего сторожа | `/api/health` |
| Журнал действий администратора | админка → «Стан системи» |
| Логи ошибок | `data/errors.log` |
| 102 автотеста | `python test_flow.py` |

## 1. Хостинг: Render (бесплатный тариф, 10 минут)

1. `render.com` → New → Web Service → подключить репозиторий `osillyt-web/sto-demo`.
2. Настройки:
   - Runtime: **Python**
   - Build: `pip install -r requirements.txt`
   - Start: `python server.py`
3. Переменные окружения (Environment):
   - `ADMIN_PASSWORD` — **свой пароль, не admin123**
   - `SITE_URL` — адрес после первого деплоя (например `https://sto-demo.onrender.com`)
   - `HOST` = `0.0.0.0` (иначе сервер слушает только локальный адрес)
4. Нажать Create. HTTPS и сертификат Render выдаёт сам.

Ограничения бесплатного тарифа: сервис засыпает после 15 минут без запросов, первый запрос
после сна — до 50 секунд. Для реального клиента берите тариф $7/мес или VPS.

## 2. Свой домен

1. Купить домен: `.com.ua` ~300 грн/год (hostiq, ukraine.com.ua), `.com` ~$10.
2. В Render: Settings → Custom Domain → добавить `sto-client.com.ua`.
3. У регистратора прописать CNAME на адрес, который покажет Render.
4. После привязки: поменять `SITE_URL` на новый домен и перезапустить сервис — от этого
   зависят `canonical`, `sitemap.xml` и ссылки в напоминаниях.

## 3. VPS вместо Render (когда нужен контроль)

```bash
# Ubuntu 24.04
sudo apt update && sudo apt install -y python3 nginx certbot python3-certbot-nginx
git clone https://github.com/osillyt-web/sto-demo.git /opt/sto && cd /opt/sto
sudo useradd -r -s /usr/sbin/nologin sto && sudo chown -R sto:sto /opt/sto
```

`/etc/systemd/system/sto.service`:

```ini
[Unit]
Description=avtokrapka site
After=network.target

[Service]
User=sto
WorkingDirectory=/opt/sto
Environment=HOST=0.0.0.0
Environment=PORT=8000
Environment=ADMIN_PASSWORD=свой-пароль
Environment=SITE_URL=https://sto-client.com.ua
ExecStart=/usr/bin/python3 server.py
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now sto
sudo certbot --nginx -d sto-client.com.ua      # HTTPS и автопродление
```

Nginx проксирует `127.0.0.1:8000`. База и копии лежат в `/opt/sto/data` и `/opt/sto/backups` —
добавьте их в ежедневный бэкап сервера (`rsync` или `restic` в облако).

## 4. Telegram-уведомления о заявках

1. В Telegram: `@BotFather` → `/newbot` → имя → получить токен вида `123456789:AA...`.
2. Написать своему боту любое сообщение (иначе он не сможет писать первым).
3. Узнать `chat_id`: открыть `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и взять
   `message.chat.id`.
4. В админке → панель Telegram: вставить токен и chat_id, включить уведомления,
   нажать «Перевірити» — бот пришлёт тестовое сообщение.

Пока токена нет, заявки всё равно сохраняются в базе и видны в админке — ничего не теряется.

## 5. Резервные копии и восстановление

Копия делается сама: при старте (если последней нет или она старше 20 часов) и далее
каждый день в 03:00. Хранятся 7 последних в `backups/`.

Ручная копия:

```bash
python server.py --backup
```

Восстановление (сервер лучше остановить):

```bash
cp backups/sto-20261106-030000.db data/sto.db
```

Проверка, что копия живая: `sqlite3 backups/sto-….db "select count(*) from leads;"`.

## 6. Мониторинг доступности

Отдайте `/api/health` любому сторожу (UptimeRobot, Better Stack, Zabbix):

```json
{"ok": true, "version": "3.2", "db": "ok", "leads": 4, "uptime_s": 3600,
 "last_backup": "sto-20261106-030000.db", "backup_age_h": 2.5}
```

Настройте: проверка раз в 5 минут, тревога при `ok != true` или коде не 200.
Дополнительно стоит проверять, что `backup_age_h` меньше 30 — иначе копии перестали делаться.

## 8. Что клиент получает на руки

1. Ссылка на сайт и на админку.
2. Пароль админки (в мессенджер, не в переписку с сайтом).
3. Этот документ, адаптированный под его домен и хостинг.
4. Инструкция по отзывам — `GOOGLE_BUSINESS.md`.
5. Договорённость о поддержке: что входит (бэкапы, обновления, правки контента) и сколько стоит.

### Что владелец делает сам, без разработчика

- **Обнулить статистику посещений.** Админка → блок «Аналітика сайту» → кнопка
  «Очистити статистику» → подтвердить. Удаляются только записи о заходах (воронка,
  топ услуг, график по дням); заявки клиентов остаются. Действие необратимое.
  Нужно, чтобы начать считать с чистого листа — например, после тестов или перед рассылкой.
- **Сменить пароль админки.** Админка → «Пароль адміністратора» → текущий и новый
  (минимум 10 символов, латиница и цифры) → «Змінити пароль». Все сессии сбрасываются,
  вход — заново новым паролем.
- **Править услуги, цены, контакты, график, слоты записи** — изменения сразу видны на сайте.
- **Проверять и публиковать отзывы.** Админка → блок «Відгуки з сайту». Сверху видно,
  сколько отзывов ждёт проверки. Каждый отзыв: «Опублікувати» — появляется на сайте
  (в блоке на главной и на странице «Відгуки»), «Зняти з публікації» — снова уходит
  в ожидание, «Видалити» — убирается навсегда. Отзывы приходят со страницы `/reviews`;
  до нажатия «Опублікувати» на сайте их не видно — так в блок не попадёт реклама и спам.
  О новом отзыве приходит сообщение в Telegram, если уведомления включены.

## Браузеры и устройства

Сайт проверен на реальном телефоне и на компьютере. Ниже — что именно проверено, а что нет.
«Проверено» означает: открыли и посмотрели глазами, а не «так должно быть».

| Браузер | Где проверено | Состояние |
|---|---|---|
| Chrome (последняя версия) | телефон Android 13, компьютер | работает |
| Firefox (последняя версия) | телефон Android 13 | работает: вёрстка, календарь дней, слоты по часам |
| Chromium-браузеры (Edge, Opera, Vivaldi, Brave, Samsung Internet) | на движке Chromium проверено на ПК | работают: тот же движок, что у Chrome |
| Safari на iPhone / iPad | движок WebKit прогнан на ПК (25/25), сам iPhone не проверяли | **движок работает**; при первом заходе с iPhone стоит посмотреть глазами |
| Internet Explorer | — | не поддерживается (браузер снят с поддержки в 2022) |

Минимальные требования: браузер не старше ~2021 года. Сайт использует обычные HTML/CSS/JS
без экзотики: `flex/grid`, `IntersectionObserver`, `fetch`. Полифилы не нужны.

Что важно знать владельцу:

- на телефоне адрес должен начинаться с `https://` — иначе Chrome показывает «Небезопасно»,
  а браузер может блокировать часть функций. Это решается установкой HTTPS на домене;
- блок записи показывает только свободные часы: прошедшие помечены «минуле», воскресенье — «зачинено»;
- количество мест на час (по умолчанию 2) и рабочие часы меняются в админке и сразу видны на сайте;
- если клиент жалуется «не открывается» — в 9 случаях из 10 это старый браузер или кэш;
  первое действие — `Ctrl+F5` (на телефоне: настройки → очистить кэш).
